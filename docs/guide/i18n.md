# Internationalization

Chat UI ships English (`en`) and Turkish (`tr`). You can replace any string, and add other languages by supplying their strings.

## Which language is used

In order:

1. the `locale` prop of `Chat` (or of a `ChatI18nProvider`);
2. the locale of an enclosing `ChatI18nProvider`;
3. the `?lang=` query parameter of the page (`en`, `tr`, or a code you supplied strings for);
4. `defaultLocale` (default `en`).

```tsx
// Uses ?lang=tr when the page has it, English otherwise
<Chat baseUrl="/api/agents" agentId="assistant" />

// Fixed
<Chat baseUrl="/api/agents" agentId="assistant" locale="tr" />

// Controlled by your app
<Chat baseUrl="/api/agents" agentId="assistant" locale={locale} onLocaleChange={setLocale} />
```

## Replace strings

`Chat` takes `customMessages`, keyed by locale code and message key (the keys are in `src/locales/en.json`):

```tsx
<Chat
  baseUrl="/api/agents"
  agentId="assistant"
  customMessages={{
    en: { "chat.input.placeholder": "Ask the support assistant..." },
    tr: { "chat.input.placeholder": "Destek asistanına sorun..." },
  }}
/>
```

## Around `Chat`

`Chat` honours a `ChatI18nProvider` around it. Its locale applies (unless `Chat` is given a `locale`), and its custom messages are merged under the ones given to `Chat`:

```tsx
import { Chat, ChatI18nProvider } from "@cognipeer/chat-ui";

<ChatI18nProvider locale="tr" customMessages={{ tr: { "chat.input.placeholder": "Bir şey sorun..." } }}>
  <Chat baseUrl="/api/agents" agentId="assistant" />
  <OtherChatUiPieces />
</ChatI18nProvider>
```

Use the provider when other parts of your page (a header built with `useI18n`, a custom message list) should speak the same language as `Chat`. `Chat` also works with no provider at all, and so do `useChat` and the components: outside a provider they answer in English.

## Another language

Any locale code works once its strings are supplied. Keys you leave out fall back to English, key by key, so a partial translation is fine:

```tsx
<Chat
  locale="de"
  customMessages={{
    de: {
      "chat.input.placeholder": "Nachricht eingeben...",
      "chat.input.send": "Senden",
    },
  }}
/>
```

Number, date and relative-time formatting use the locale code (a code the browser does not know formats as English).

## Error messages

A failed request whose `code` the library knows is shown with a localized message instead of the server's English text: `chat.error.code.<code>` (the code in lower case). Example keys: `chat.error.code.conversation_busy`, `chat.error.code.rate_limited`, `chat.error.code.action_expired`, `chat.error.code.file_too_large`. A few strings contain `{detail}`, which is replaced with the server's own message (`validation_error`, `guardrail_blocked`, `file_too_large`, ...). Override them like any other string:

```tsx
customMessages={{ en: { "chat.error.code.rate_limited": "Slow down a little, please." } }}
```

The error object keeps its `code` and `status`; the server's wording is on `serverMessage`. See [Approvals and Questions](/guide/approvals#errors).

## In your own components

```tsx
import { useI18n } from "@cognipeer/chat-ui";

function Greeting() {
  const { t, has, locale, setLocale } = useI18n();
  return (
    <button onClick={() => setLocale(locale === "en" ? "tr" : "en")}>
      {has("chat.empty.subtitle") ? t("chat.empty.subtitle") : "Hello"}
    </button>
  );
}
```
